# DeviceLayoutLab 后端物理实现教学方案

日期：2026-09-29。状态：产品取舍已逐项确认；用户已授权启动首版开发。当前先实现 Windows 开发、Linux 部署的网页与独立后端骨架；ORFS 环境接入、Blender 资产生产与真实流程运行仍须分别核验。

## 1. 产品目标与已确认边界

产品是一套面向课堂演示与学生探索的网页，让用户从后端设计中的一个对象或问题出发，在二维版图、局部三维、单元结构、电路连接、工艺资料和工具结果之间寻找依据。

核心教学问题：这是什么、为什么在这里、与谁连接、什么规则约束它、改变它会发生什么，以及工具如何检查。

已确认：

- 独立项目，前端网页 + 独立后端调用 ORFS；不连接同级教学平台。
- Blender + Three.js；基础案例包含三类教学器件与反相器/NAND2。
- 覆盖平面 MOS、FinFET、GAA，CMOS 作为电路构成而非第四种器件结构。
- 首先服务后端物理实现和认识工艺库，器件模型用于解释相关结构。
- 优先标准单元、物理单元、金属层、走线、闩锁与天线效应；空间电场求解及与后端关系弱的器件现象暂缓。
- 后期接入 Agent；当前先开发不含 Agent 的基础工作台，不运行 EDA。
- 工程工作台为主，配预设案例；不包含答题、测验、评分或预测作答。
- 首版真实设计侧只开放参数调整和配方运行；教学副本提供自由移动与拆解。此项已由用户确认，不再作为待决策问题。
- 默认展示几行标准单元组成的局部版图；单元内部与完整设计作为两端视图。此项已由用户确认。
- 案例来源采用双轨：编排好的教学场景为默认入口，真实 ORFS 案例用于切换、追踪与参数实验；两者共用交互并明确标示来源。此项已由用户确认。
- 主画布采用二维、三维并排联动，选取同步，任一视图可最大化。此项已由用户确认。
- 首版工艺深度分层推进：三类均有可拆解教学结构；先以 SKY130 完成真实闭环，FinFET/GAA 的库资料和实际单元按可获取资产接入，真实流程随后扩展。此项已由用户确认。
- 设计入口分阶段：首版只开放预设案例，最终目标支持用户导入 RTL/约束与后端产物、运行 ORFS 并探索结果。此项已由用户确认。
- 第一条完整 ORFS 案例是教学专用小型数据通路：输入寄存器 -> 加法/选择等组合逻辑 -> 输出寄存器，承载流程、阶段对比与参数实验。INV/NAND2 作为单元内部案例保留；具体位宽与规模尚待确定。此项已由用户确认。
- 首版参数面板采用少量核心参数 + 专项配方，每项有解释与运行前后对比；不以完整分阶段参数面板为首版目标。此项已由用户确认。
- 课堂采用预先真实运行 + 按需重跑：已有基线、阶段快照与典型参数对照可直接查看；用户修改参数后点击运行提交 ORFS，明确区分已有结果与本次执行。此项已由用户确认。
- 首版部署一台 Linux 服务器，集中运行教学后端与 ORFS，教师/学生经浏览器访问，真实任务集中排队。此项已由用户确认。
- 首版真实实验先服务个人提交；多用户管理后续扩展，不作为首版验收要求。此项已由用户确认。
- 三维默认教学展开，可切回原始比例；放大及层间展开明确标示，二维保持原始平面几何，源几何和尺寸依据保留。此项已由用户确认。
- 首版教学副本只做展示性移动与拆解，保留原电气连接并提供位置/连接参照；故障编辑不属于首版。此项已由用户确认。
- 后期 Agent 优先场景操控 + 对象讲解；采用用户提供密钥调用 DeepSeek、GLM 等 API。密钥仅保存于后端会话内存，会话到期或服务重启后重新输入，不持久保存。此项已由用户确认。
- Agent 首次接入以结构化对象、网络、可见图层、剖面状态和工艺资料为主，通过稳定对象 ID 操作；截图理解后续扩展。此项已由用户确认。
- 首版以教学服务器可达为前提，基础网页、模型和预设结果不依赖公网资源；脱离服务器的离线查看后续扩展。外部 Agent API 另需对应网络。此项已由用户确认。
- 用户确认现有 Linux 服务器的 ORFS 已能完成真实流程，首版复用其工具环境；本项目所需版本、路径、资源和 SKY130 资产仍需实施前核验。
- 首版客户端目标是桌面电脑 Chrome/Edge，以笔记本、台式机和课堂投影为使用场景；平板、手机与触控适配不属于首版。此项已由用户确认。

首版已确认取舍与可逐项检查的验收草案汇总在 [V1_ACCEPTANCE.md](V1_ACCEPTANCE.md)。尚未逐项确认的验收细节、实施分期、后端框架与资产选择仍为提案；产品方向的确认不等于授权实施。

## 2. 用户究竟可以做什么

用户已确认“工程工作台 + 预设演示案例”。用户打开案例后直接操作，不需要先回答问题、完成题目或通过关卡。教师可以保存镜头、剖面和输入状态逐步讲解。用户可以预览已有真实结果，也可以提交受约束实验并等待 ORFS 的新结果；查看教学模型不以成功运行全流程为前提。

设计入口已确认分阶段：首版用户只能选择预设案例、允许参数与登记配方，不提供自定义 RTL 或后端产物上传入口。最终产品保留两类导入目标：用户 RTL/约束的真实 ORFS 执行，以及匹配已支持工艺的后端产物探索。后续接入需处理文件完整性、工艺/库身份、约束、连接与对象映射，不因首版采用固定案例而将该目标删除。

| 用户任务 | 可操作内容 | 可观察效果 | 数据依据 |
| --- | --- | --- | --- |
| 认识工艺库 | 选择已支持工艺、单元库、角和文件视图 | 对照 LEF、Liberty、GDS 与网表描述同一个单元 | 原始资产及解析结果 |
| 认识标准单元 | 选择 INV/NAND/BUF/DFF；展开引脚和内部结构 | 逻辑、电路、二维版图与局部三维同步定位 | 经核验的库单元和对象映射 |
| 认识物理单元 | 按用途筛选 tap/endcap/filler/tie/decap/diode | 在行中定位，展开结构，说明电源/阱/栅的连接作用 | 工艺库与教学模板分别标注 |
| 理解放置 | 显示 row/site、镜像与电源轨；拖动教学副本 | 显示重叠、对齐、边界及合法化前后变化 | 教学几何检查；真实检查另列 |
| 理解互连 | 选择网络、逐层追踪、剖切、展开过孔 | 对照端子连通图，看到不同层上的路径 | ODB/DEF、tech LEF 与提取依据 |
| 理解时序 | 选择报告中的路径，比较阶段和变体 | 在版图定位路径，区分单元与网络延迟 | 时序报告、约束与寄生模型 |
| 理解流程 | 切换 floorplan/place/CTS/route 等快照 | 看到新增/移动的单元、路由和指标变化 | 各阶段真实产物；缺失明确显示 |
| 理解闩锁与 tap | 调整教学 tap 分布，剖开阱与衬底 | 显示接触、偏置、寄生 PNPN 示意和规则关系 | 工艺特定教学模型/规则，不作可靠性预测 |
| 理解天线与修复 | 按制造阶段查看连接，选择工具标记网络 | 显示阶段性收集区域、受影响栅与修复前后 | 工艺天线规则、检查/修复报告 |
| 做参数实验 | 修改允许的利用率、放置密度、路由层等 | 等待工具执行，对比版图、拥塞、时序与失败 | 固定其它条件的独立 ORFS 运行 |
| 保存课堂场景 | 保存对象、镜头、图层、剖面、阶段和解释 | 复现讲解顺序；以后可导出截图/视频 | 场景书签与对应资产版本 |

用户界面强调教学任务，不把解析器、执行协议等实现细节放入教学流程。高级视图可查看来源与工具记录。

## 3. 页面形态

主舞台已确认是几行标准单元组成的局部版图，可观察逻辑单元、该案例实际存在的物理单元、电源轨及信号互连。点击单元进入内部，点击网络展开局部三维；完整设计用于整体定位、流程和指标查看。案例来源已确认为双轨，首批对象组合尚待确认。

双轨案例：教学场景使用真实库单元，人工组织有利于讲解的布局与连接；真实案例来自 ORFS 原始产物。默认打开编排教学场景，用户可切换真实案例。两者共用选择、剖切、图层和资料联动，但对象身份、布线依据和报告归属分别维护。人工布局、教学连接或自由修改不声称已经工具验证，真实案例只呈现实际存在的对象。单元资产身份可以共用，位置和拓扑不强制一一对应。

建议是一个工作台，三个教学入口共用对象和视图：

1. 工艺库：从工艺和单元目录进入。
2. 版图探索：从设计快照、单元实例或网络进入。
3. 预设演示：直接打开准备好的场景和结果，按需回放操作步骤或自由修改教学副本。

布局建议：左侧为对象/图层导航，中间为并排的二维与三维主画布，右侧为所选对象的说明、参数与相关资料，底部为流程阶段、对比和工具报告。两幅主画布默认同时显示同一局部场景，任一视图可单独最大化；原理图和工艺资料按需展开。

同一对象使用稳定语义 ID：选中实例、库单元、引脚、网络、晶体管、过孔或报告标记时，各视图联动；无法建立可靠映射时明确显示映射缺失。

默认二维与三维并排联动，选中任一视图中的对象后另一视图同步高亮并可定位；进一步展开单元内部或剖切器件。二维用于平面位置与连接，三维用于空间结构，细节按局部范围加载。网络颜色、材料颜色、单元用途颜色与工具数值热图是不同显示模式，需分别给出图例。

客户端范围已确认桌面 Chrome/Edge，优先鼠标与大屏并排操作；首版不验收移动端/触控布局。具体参考电脑、显示分辨率、帧率与模型预算将在环境核验后确定，当前不编造性能达标结论。

## 4. 工艺库学习如何落地

用户选择工艺后看到该工艺实际可用的资产和功能，不将某个文件缺失误写成整个工艺不可用。

| 视图 | 教学内容 |
| --- | --- |
| 技术 LEF | 路由层、cut 层、pitch、width、方向、via、site 等已提供信息 |
| 单元 LEF | 边界、引脚形状、阻挡；解释后端为什么用抽象视图 |
| Liberty | 功能、引脚、时序弧、输入电容、驱动版本、PVT 条件 |
| GDS/OASIS | 单元内部图形及层/用途；展示抽象省略了什么 |
| SPICE/CDL/器件模型 | 仅在已提供并核验时查看内部连接与电气定义 |
| 规则与工艺栈 | 间距、接触、天线、阱/衬底约束和三维高度的依据 |

库单元 master 与设计 instance 必须区分：修改相机或教学模型不等于修改库；同一 master 可以有多个不同位置与朝向的实例。

单元角色分类结合库文档、LEF class、Liberty 功能、供电/端口信息和已审映射，不能只依靠名字关键词或 LLM 猜测。有的单元兼具功能，有的工艺使用 tapless 架构或不同边界方案，界面需反映该库事实。

三类工艺的状态分别登记：教学结构可用、库资产可读、对象映射可用、三维参数有据、ORFS 可运行、专项检查可运行。初始候选为 SKY130、ASAP7、PKP3；ASAP7 与 PKP3 是不可制造的预测 PDK。并不预设 PKP3 已兼容 ORFS。

首版深度已确认采用分层推进，首条真实闭环优先 SKY130。三类教学结构属于首版要求；首版不要求三套工艺真实运行达到相同深度。实际库/单元的展示由已获取且核验的资产决定，之后扩展 FinFET/GAA 的真实流程；未就绪能力明确标示，不用其它工艺结果替代。

单位、节点名、数据库缩放与展示放大分开记录；不能由“7nm/3nm”反推全部实际尺寸，也不能直接拼接不同库版本的文件。

## 5. 物理单元是第一批重点内容

| 对象 | 主要教学关系 | 可视化提案 |
| --- | --- | --- |
| Tap cell | 阱/衬底接触及电位约束；具体取决于工艺 | 行内分布、接触到电源、局部阱截面；规则相关距离示意 |
| Endcap/boundary cell | 行边界、工艺终止及库要求 | 行两端及切行后的边界，展开相邻层结构 |
| Filler cell | 在适用库中填行间空隙、保持相应结构连续性 | 插入前后对照及边界拼接；不声称所有 filler 结构相同 |
| Tie-high/tie-low | 工艺要求的常量驱动与负载连接 | 常量网络、tie 输出与负载引脚；与 tap 明确区分 |
| Decap cell | 局部供电去耦 | 电源/地连接与电容结构示意；暂不定量声称瞬态改善 |
| Antenna diode | 工艺相关天线保护 | 栅网络与二极管连接、制造阶段和工具修复对比 |
| Clock buffer/inverter | 时钟分发和时序 | CTS 新增实例、拓扑、树深与实际延迟/偏斜报告 |
| Metal fill | 满足相关金属密度要求 | 空白区域填充与密度窗口；不是 filler cell，也不默认与信号相连 |

真实案例只展示该 PDK 实际存在并有依据的对象。其它角色用标注的教学模板说明，不能放入真实运行结果冒充插入产物。

OpenROAD 具有 tap/endcap 插入、filler 放置等能力；其具体设置及该平台单元支持需要逐项验证。

参考：[Tapcell](https://openroad.readthedocs.io/en/latest/main/src/tap/README.html)、[Detailed Placement](https://openroad.readthedocs.io/en/latest/main/src/dpl/README.html)。

## 6. 重点实验及效果

### E1：同一单元为什么有不同文件

选择同一版本的 INV/NAND2，切换 LEF、GDS、Liberty 和晶体管连接。点击一个引脚，查看后端使用的引脚形状、内部连接及功能定义。比较驱动版本，展示面积/输入电容/时序条件；不把驱动后缀解释成所有量等比例变化。

验收：能从抽象引脚定位真实几何，理解单元 master 与 instance，知道哪类问题应查哪类文件。

### E2：把单元放进标准单元行

教学副本中移动、镜像单元，显示 site 对齐、重叠、电源轨关系。运行允许的真实放置配方后，看合法化移动以及 tap/endcap/filler 等已执行阶段的变化。镜像使用库允许的 symmetry，不任意旋转所有单元。

验收：教学几何错误能被识别，实际工具结果与原始快照分开保存。不能将启发式几何检查称为完整工艺 DRC。

### E3：从一个引脚沿走线追到另一个引脚

在二维网络上选择端点，依次显示接触、局部互连、路由金属和过孔；局部三维展开各层，剖面与二维切线同步。采用选定工艺的层名称与实际路径。

提供两种可直接切换的演示状态：二维交叉但不相连、存在正确过孔才相连。连接依据来自数据库或提取图，而不是屏幕上的重叠。

验收：保持网络身份、via 层对和端点连通；爆炸视图不得篡改原始结构。

### E4：闩锁效应为什么与 tap 和版图有关

先以已选平面体硅工艺的简化截面与寄生 PNP/NPN 电路展示再生导通机制，再显示阱/衬底接触如何参与电位约束。改变教学 tap 分布可显示距离关系与工艺规则说明，避免使用无依据的“闩锁风险百分比”或电场云图。

真实流程可比较 tap 插入方案，但 ORFS 放置与距离图本身不能证明闩锁安全；完整判断需要相应工艺规则和验证环境。FinFET/GAA 的结构与规则须按具体工艺说明，不能照搬同一体硅模型，也不能宣称天然免疫。

验收：学生能区分 tap 与 tie；知道物理单元如何服务后端约束，也知道规则示意的适用范围。

参考：[SKY130 工艺假设及闩锁规则](https://skywater-pdk.readthedocs.io/en/main/rules/assumptions.html)。

### E5：天线效应为什么最终连通还不够

用明确标注的制造阶段示意，解释加工过程中已经形成的导体与栅连接关系如何变化；它与成品芯片对无线电的接收不是同一概念。

选择工具报告中的网络，展示参与面积/周长、栅面积、适用的分层/累积规则，以及二极管修正等工艺信息。可以展示保护二极管、改变层间连接等教学策略，但实际修复方式以选定工具和平台支持为准。

真实流程路径是检查 -> 定位 -> 受支持修复 -> 重新检查，保留前后结果。OpenROAD 有天线检查与全局路由修复接口，具体工艺规则覆盖需核查。制造动画不宣称由 ORFS 自动还原完整工艺历史。

验收：用户能解释“最终已经连接”不能代替制造阶段检查；不能把所有天线规则缩减成导线长度/栅面积。

参考：[OpenROAD Antenna Checker](https://openroad.readthedocs.io/en/latest/main/src/ant/README.html)、[Global Routing](https://openroad.readthedocs.io/en/latest/main/src/grt/README.html)、[SKY130 天线规则](https://skywater-pdk.readthedocs.io/en/main/rules/antenna.html)。

### E6：增加密度或限制路由层会发生什么

使用同一小型设计、工艺、库角、约束和工具版本，改变一个允许参数，比较放置、拥塞、走线、过孔、时序及失败。只显示报告提供的指标，变化不必单调，失败是学习结果的一部分。

利用率和放置密度作为不同参数解释，不能混为一谈。拥塞图优先使用路由需求/容量报告；由几何推算的密度图单独命名，不能冒充工具拥塞。

验收：实际生成不同配置并完成/明确失败，结果能追溯到各自运行。

### E7：工具为什么插入缓冲器

首条真实案例已确认使用教学专用小型数据通路，结构为输入寄存器、加法/选择等组合逻辑、输出寄存器。它同时服务真实流程、阶段对比和参数实验；具体位宽、算术/选择功能和规模将在案例定义时确认。

用该带寄存器的数据通路观察 CTS 与时序优化；区分信号缓冲器和时钟树。点击报告路径，在真实布局上显示节点、网络与延迟来源。案例规模应兼顾局部可读性与参数实验可观察性；过小设计未产生某种现象时如实标明，不能编造拥塞或插入结果。

纯 INV/NAND 组合案例不用于声称展示了完整 CTS。由不同阶段估计/提取的寄生分别标记，不能把早期估计当最终路由实测。

E1–E5 为建议的首批教学主线；E6 中一个受约束参数变体随第一条 ORFS 纵向切片接入，更多参数及 E7 专项展示逐步扩展。

## 7. 视觉效果与建模要求

- 多层金属可透明、隔离或爆炸展开；相关网络保持高亮，其余淡化。
- 可移动剖切平面显示器件/接触/via 的局部结构；剖面必须有清晰切面或轮廓，避免只看到空壳。
- 二维转三维保留选择和相机参照；空间高度来自工艺配置，教学放大明确提示。
- 默认展示方式已确认教学展开：可放大薄层、拉开层间距离，显示接触、via 和器件部件；放大倍率与展开状态明确标示，并提供切回原始比例的操作。二维仍使用原始平面几何，三维展示变换与源尺寸独立。原始比例模式也注明工艺来源及重建假设，不将假设高度称为制造实测。
- 同一器件三类结构可以并排观看，重点解释栅/沟道与版图约束；不自动比较不同节点的性能优劣。
- 制造阶段、插入前后、合法化前后和路由前后均由教学任务驱动，不追求全程粒子动画。
- 三维构造采用带语义 ID 的部件，Blender 源文件可编辑；GLB 是展示资产，不是浏览器中的 Blender。
- 参数定义集中保存，浏览器几何变化与 Blender 构造一致。工艺标记层、掩膜层不一律挤出成实体材料。
- 首版拆解语义已确认只改变展示：移动部件、揭开栅、分离层或单元时，保留原始电气连接，提供原位置与连接参照，并可恢复。显示的拆解距离不作为真实导线长度或寄生输入。故障编辑、移除接触导致断路等能力留到后续单独讨论，不混入首版拆解操作。
- 单元库几何复用、实例化与按需细节控制用于大设计；完整芯片默认二维，只在局部加载器件细节。

时序路径“脉冲沿线播放”只能表示报告顺序和延迟，不宣称真实电子轨迹。数值热图必须有单位、条件和来源。

## 8. 前端、后端与 ORFS 的职责

```text
教学网页：二维版图 + Three.js 局部三维 + 电路/资料/报告联动
    ↓ 受约束的查询、场景操作和实验请求
独立教学后端：案例、工艺能力、任务、快照、报告与对象映射
    ├─ 工艺/单元资产读取与预处理
    ├─ Blender 建模与导出（离线或异步任务）
    └─ ORFS 适配器 → 已配置的 Linux 工具环境
          → OpenROAD/Yosys/KLayout 等
          → 原始产物、报告、日志与阶段快照
    ↑ 派生视图引用原始证据
后期 Agent：通过同一查询与实验接口协助学习
```

即时操作：相机、选择、图层、剖切、教学模型参数和已有结果回放。真实运行：修改密度/层限制、插入/修复、重跑合法化/路由/时序等，必须显示排队、运行、失败和结束状态；不能承诺每次拖动都即时完成 ORFS。

首版参数方式已确认：少量核心参数 + 专项配方。候选参数为利用率、放置密度、路由层范围和时钟周期等；tap 插入、天线检查与修复以已登记且验证的专项配方执行。每项展示概念、单位、适用阶段和结果对比。具体参数清单、范围、默认值与依赖通过工艺和首条案例核验后确定；不开放尚未证明进入工具且生效的配置。配方次序遵守工具要求，不任意拼接阶段。

课堂运行方式已确认采用预先真实运行 + 按需重跑。预先准备首条设计的基线、可用阶段快照及典型参数变体，所有展示数据保留真实运行来源，打开案例即可查看。用户修改参数不会自动触发每次滑动都启动 ORFS，点击运行才提交新任务；等待时仍可操作模型和浏览已有结果。若已有匹配结果可查看，明确显示其原始配置、版本和运行身份；本次任务的排队/执行/失败状态另行显示，不用旧结果冒充新执行。

首版编辑边界已确认：真实快照只读，真实变体由允许参数和登记配方生成。教学副本的自由移动、拆解仅为展示变换，保留原电气拓扑；界面明确标识副本与展示状态，操作不进入真实 ORFS 输入，不宣称报告反映展示位移后的结构。原始报告仍只对应源快照。副本创建和恢复保留真实来源关系，首版不提供改变连接的故障编辑。

首选后端组织提案为 Python 服务加一个有界任务执行器；具体 Web 框架与队列实现待确认。首版部署方式已确认一台 Linux 服务器集中运行教学后端与 ORFS，教师/学生通过浏览器访问，统一工具与工艺库版本，真实任务集中排队；不要求每台学生电脑部署 ORFS。已有工具环境只读复用，输入、输出与日志独立；不依赖同级平台数据库或服务。实际服务器身份、资源与工具可用性仍需实施前核验，当前没有环境验收声明。

首版真实提交规模已确认是个人使用。首版记录案例、任务、参数、状态和产物，隔离各任务工作区，不实现班级管理、多用户权限/配额或用户间结果管理。任务执行并发上限依服务器资源核验配置；未来多用户身份和管理留有接口边界，但不预建完整多租户系统。浏览器查看预设案例的部署不改变首版真实提交范围。

首版网络边界已确认：浏览器需能访问教学服务器；基础网页依赖、模型、已准备案例、报告与已核验资料由服务器提供，运行期不依赖公网 CDN 或在线资料服务。新 ORFS 任务在服务器环境执行；外部 Agent API 另需服务器访问相应供应商接口。首版不实现浏览器脱离服务器的离线缓存/案例包，后续可扩展。依赖安装与资产准备阶段的网络需求单独审计，不将运行期内网可用等同于安装期完全离线。

现有环境状态：用户确认已有 Linux 服务器，ORFS 可完成真实流程。首版以只读复用现有工具环境为基础，P0 核验确切版本、资源、路径、可用工艺库和执行入口，不默认安排重装工具链。用户确认是规划依据，不构成本项目的环境/案例验收证据；尤其不推定 SKY130、专项规则与每个目标单元已验证。当前开发网页和服务骨架，但在未取得服务器连接信息并完成核验前，不远程连接或运行任务。

ORFS 主要负责已有库上的综合、物理实现和分析，不设计晶体管内部版图，不生成完整器件三维结构。专项工艺 DRC/LVS 或规则未覆盖的检查需要单独适配已有验证设施。

ORFS 各阶段产物需依据锁定版本枚举，不硬编码所有版本都有同一快照。只在完整输出可读取时发布阶段视图。分阶段继续执行需核对依赖；学生的新变体不覆盖既有运行。

最小执行记录：案例/输入身份、PDK/库/工具版本、参数与单位、实际配置、约束、运行日志、状态、产物身份与来源。不存在的阶段和报告明确标为缺失。

数据流区分三条映射：设计实例与 master、网络与实际互连、单元内部晶体管与几何。内部映射缺失时仍可展示可靠的后端抽象，不能猜造内部对应。

参考：[ORFS 流程教程](https://openroad-flow-scripts.readthedocs.io/en/latest/tutorials/FlowTutorial.html)、[流程变量](https://openroad-flow-scripts.readthedocs.io/en/latest/user/FlowVariables.html)。

## 9. 后期 LLM/Agent 可以做什么

优先能力已确认场景操控 + 对象讲解：用户以自然语言指定对象、图层、剖面或网络，Agent 操作已有视图并结合来源解释；随后扩展实验规划与结果诊断。接口在基础平台阶段预留，Agent 在真实数据与操作稳定后接入。

模型来源已确认用户提供 API 密钥，调用 DeepSeek、GLM 等供应商 API。设计统一 Provider 适配边界，配置供应商、API 端点、模型身份与能力，不依赖 Codex 登录态，不在代码中写死某个模型。具体供应商、模型及地区端点须分别核验可用能力和消息格式；支持共同形式的工具调用也不意味着所有参数和推理消息可直接互换。

建议调用链：网页提交用户指令与当前场景身份 -> 教学后端组装最小对象/资料上下文 -> Provider API 返回结构化工具请求 -> 后端校验对象、参数与允许操作 -> 网页执行场景动作并反馈结果 -> Agent 解释。供应商 API 请求建议由后端发起；浏览器执行本平台的视图操作，密钥不随工具消息、报告或场景数据传播。此调用链为待审设计；密钥已确认仅保存在后端会话内存。

密钥保存方式已确认后端会话内存：会话到期或服务重启后重新输入；不提供持久保存，不写入文件、数据库或浏览器持久存储。网页输入后传给后端用于 API 请求，普通业务响应不返回密钥。密钥不得进入代码、Git、普通日志、模型消息、场景书签或导出产物。会话绑定、到期期限、主动撤销和错误脱敏需要实施时确定，未来多用户会话隔离另行扩展。当前不创建任何凭据或密钥配置。

DeepSeek 与 GLM 的官方资料均提供工具调用机制，可作为场景操作适配依据。实施时仍须对选定模型执行能力验证，并由本平台校验及执行操作，模型输出本身不构成执行成功。

参考：[DeepSeek Tool Calls](https://api-docs.deepseek.com/guides/tool_calls/)、[GLM/Z.AI Function Calling](https://docs.z.ai/guides/capabilities/function-calling)。

| 能力 | 用户例子 | Agent 依据与动作 |
| --- | --- | --- |
| 指认与讲解 | “这个没有逻辑功能的单元是什么？” | 读取实例、master 与角色依据，定位并解释 |
| 视图操作 | “只显示这条网的金属和过孔。” | 选择网络、筛选相关几何、设置相机/剖面 |
| 工艺库检索 | “这个工艺的 tap 规则在哪里？” | 检索已核验文档，引用条款与适用条件 |
| 连通解释 | “为什么这两条线交叉却不连接？” | 直接展示层、via 和数据库连接依据 |
| 报告定位 | “这条路径慢在哪里？” | 读取路径和寄生依据，在版图标注贡献；不臆测电场 |
| 对照实验 | “限制一层路由会怎样？” | 形成可审查实验提案，调用已登记配方，比较实际结果 |
| 概念对照 | “展示 filler 和 metal fill 的区别。” | 并排展示实际对象与作用，不生成练习题 |
| 教师备课 | “保存一段讲天线效应的演示。” | 组合已核验案例、镜头与说明，教师可编辑 |

Agent 首次接入已确认结构化数据优先。上下文包含当前 PDK、阶段、选中对象及稳定 ID、相关局部网络、可见图层、剖面状态、报告和资料引用，不要求每次加载整个芯片。首批不传截图、不以图像理解为必要能力；后续截图用于补充视角、遮挡和显示效果，须按选定模型能力单独接入。对象身份与电气连接仍以数据和来源为依据，不能由截图猜测。

候选工具接口：`inspect_object`、`read_library_view`、`trace_net`、`select_objects`、`set_layers`、`set_section`、`read_report`、`compare_runs`、`propose_experiment`、`run_recipe`、`save_scene`。名字是设计提案，尚未实现。

查询和相机操作可自动进行；实验遵循用户当前授权和已登记参数边界，超出边界需确认。严禁任意命令执行、修改共享原始库、编造运行结果。解释分别说明事实、假设与教学示意；缺少信息可以回答无法判断。

自然语言生成 RTL 暂不作为主链路；首版只使用固定预设设计。用户导入自己的 RTL/约束和后端产物是已确认的最终目标，独立于是否采用自然语言生成 RTL。

## 10. 实施分期

首版交付目标覆盖 P0–P2，并包括已确认的核心参数运行与前后对照；P3 中进一步的时序诊断、多工艺真实流程及 P4 Agent 属后续扩展。当前从网页与服务骨架开始，具体阶段验收见首版草案。

### P0：环境与教学案例可行性审计

核查现有 ORFS、工具版本、可获取的三类工艺资产、许可证、规则与单元；确定首批案例及参数范围。登记每个工艺独立的教学/资产/运行能力。尚不能运行的工艺不会用另一工艺结果替代。

交付：已审工艺能力表、案例定义、对象映射样例和真实运行验收计划。

### P1：工艺库工作台与首条真实 ORFS 切片

实现工艺库认识、三类教学器件、INV/NAND2、二维/三维/电路联动、图层与剖切；首先用已核验的 SKY130 资产建立真实单元对应。接入独立后端调用 ORFS，完成已确认的教学专用小型寄存器数据通路的实际流程并发布可用阶段快照；至少提供一个受约束参数变体与真实对比。优先物理单元目录与可复现课堂场景，DC 曲线等器件专题不占主线。

交付：用户能使用 E1、基础 E3，认识实际存在的物理单元，并从网页发起真实运行、查看结果与参数变体。三类结构教学均覆盖；各工艺的真实运行支持独立登记。

### P2：后端基本概念和两类效应

加入标准单元行、物理单元插入讲解、闩锁与天线教学案例；开展 E2、E4、E5。扩展 ORFS 配方；真实天线检查/修复及物理单元插入必须按该工艺能力逐项验收。

交付：至少一个真实设计的阶段快照、前后比较、报告定位；教学示意与真实运行界面明确区分。

### P3：受约束的真实实验与多工艺扩展

完成密度/路由层实验、时序路径及 CTS 等 E6/E7，扩展已审工艺库与实际单元覆盖。ASAP7、PKP3 的运行适配依实际资产和工具条件推进，最终范围保留三类结构，不静默放弃某一类。

交付：用户可提交参数实验，看到独立的成功/失败证据与对比；每类工艺的支持边界清楚。

### P4：Agent 教学与实验助手

接入用户密钥、Provider 适配、上下文、资料检索与视图控制，优先验证场景操控和对象讲解；再扩展报告解释与受约束实验。以典型指令核验对象定位、操作有效性和事实来源，再扩大自动操作范围。

交付：Agent 能在实际对象上解释并引用，不能靠流畅文本掩盖错误来源或未经执行的结论。

## 11. 验收要求

建议的首版功能验收清单与首条演示路径见 [V1_ACCEPTANCE.md](V1_ACCEPTANCE.md)。清单均为计划要求，尚未验证通过。

个人提交之后扩展多用户身份、任务配额、用户间结果隔离和管理；这些能力不属于首版验收。

- 演示：每个案例有概念说明、可直接执行的操作、可观察变化及适用范围；不包含用户作答、自动出题或学习评分。功能验收检查操作和结果可复现。
